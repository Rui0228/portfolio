硬件 AI 工作流

一套基于 Claude Code 的硬件设计协作方法论。把"从想法到原理图"的完整流程拆解为可确认、可回溯的阶段性步骤，让 AI 成为可靠的硬件设计搭档——不替人做决定，但把每一步的决策依据、元件参数与检查要点都摆到台面上。

🧩 硬件项目渐进式构建 · Incremental Build

传统做法是"一次性输出全部设计"，但硬件设计的容错率极低——一个引脚接错，整板报废。这个工作流把硬件设计拆成六个可确认的阶段，每走一步都停下来等确认，杜绝"AI 猜对了架构、却猜错了接线"的风险。

🗺️ 六阶段流程 · Pipeline

① 系统架构树 —— 从顶层到底层树状展开，标注关键元件、GPIO 分配、信号流向与设计约束
② 电路设计原理详解 —— 每个模块讲清"是什么、为什么、怎么工作"，含关键公式与电流路径
③ 电子元件清单 —— 按模块分组，每项给推荐型号 + 搜索关键词 + 必须满足的参数
④ 逐模块渐进式确认 —— 一个模块确认完、给完接线说明，才进入下一个
⑤ 原理图检查核对清单 —— 逐项列出检查点，覆盖常见错误（电阻值、二极管方向、分压比）
⑥ PCB 检查清单 —— 布线规则与核对项（持续迭代中）

⚙️ 核心原则 · Principles

一步一确认 —— 每完成一阶段，等用户确认后再前进，不主动跳步
不替用户做决定 —— 元件选型给推荐而非唯一答案，最终选择权在用户
用引脚功能名，不用位号 —— 写"DW01 的 DOUT 接 FS8205A 的 G1"，而非"DW01 Pin1 接 U4 Pin2"
给搜索关键词，不给商品编号 —— LCSC 编号可能失效，搜索关键词 + 参数才是硬标准

🔌 硬件电路渐进式确认 · Progressive Verification

在元件清单确定后，这套流程负责"确认一个、连接一个"，直到原理图完成。它的价值在于：把抽象的电路连接关系，用引脚功能名和 ASCII 接线图一步步落地，让每个连接都能追溯到数据手册依据。

📋 元件清单写法 · BOM Format

每个元件标注"必须满足的参数"——如果换型号，哪些指标不能妥协。例如：
电阻 100kΩ 0603 ±1% —— 必须 1% 精度，不能降为 5%
SS34 肖特基 —— 必须 Vf<0.5V@1A、VR≥40V，是肖特基而非普通整流管
DW01-A 保护芯片 —— 必须确认引脚排列，不同尾缀排列可能不同

🛠 PCB 布线规则 · Layout Rules

走线宽度按电流计算 —— 按 IPC-2221 标准，先算电流再定线宽，不拍脑袋
噪声源 vs 敏感目标 —— 只有交变信号才会吵，只有模拟/高阻抗信号才会被吵；DC 不扰 DC
退耦电容紧贴 IC —— 电容位置比线宽重要，走线长度对滤波效果影响更大
危险引脚防护 —— 明确列出禁止引出或需固定电平的引脚（如 ESP32-S3 的 GPIO45）
